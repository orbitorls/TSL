# TSL Website - Model runtime notes

This document explains where to place the ONNX model used by the server-side inference API and how to run the prediction endpoint locally.

## Where to put the ONNX model

- Default path (used by the API route):
  - `D:/TSL/models/tsl51_gru_20260413_120426.onnx`
  - The Next API route expects the model at `../models/tsl51_gru_20260413_120426.onnx` relative to the `tsl-website` folder. That resolves to the `models/` directory in the repo root.
- Custom path:
  - You can override the ONNX model file path with an environment variable:
    - `TSL_ONNX_PATH=/absolute/path/to/tsl51_gru.onnx`

## Installing ONNX runtime (optional)

If you want the API to run real ONNX inference (instead of falling back to the built-in mock), install the Node native runtime:

```bash
cd tsl-website
npm install onnxruntime-node
```

Note: `onnxruntime-node` is a native package. On some platforms you may need build tools or to use a prebuilt binary.

## Next runtime requirement

The API route is configured to use a Node runtime (server-side native module support). This is set in `app/api/predict/route.ts` via `export const runtime = 'nodejs'`.

## Example: call the API

Send a JSON POST to `/api/predict` with a `features` field that is an array of 162 numbers (float values). Example using curl (synthetic features):

```bash
curl -sS -X POST http://localhost:3000/api/predict \
  -H "Content-Type: application/json" \
  -d '{"features": [0.0, 0.1, -0.2, /* ... 162 values total ... */ ] }'
```

Example successful responses (shapes you may see):

- Fallback/mock (server could not load onnxruntime-node or the model):
  ```json
  { "prediction": "สวัสดี", "confidence": 0.72, "fallback": true }
  ```

- ONNX inference (example):
  ```json
  { "predictionIndex": 12, "confidence": 0.84, "rawScores": [0.1, -0.5, 2.3, ...] }
  ```

Notes:
- `predictionIndex` is the class index (0-based) of the best-scoring class in the ONNX model output. You can map this to a label using the same CLASSES list defined in `lib/model.ts`.
- The server will fall back to the mock predictor if the ONNX model or runtime cannot be loaded; this keeps the UI functional during development.

## Troubleshooting

- If you see `ONNX model not found` in server logs, verify `TSL_ONNX_PATH` or put the model file at the default path above.
- If you see native build errors while installing `onnxruntime-node`, try using a platform-matching prebuilt or consult the package docs for platform-specific instructions.
